# Установка Apache Kafka

Kafka работает как сервер, который называют брокером. Брокер хранит топики, а консольные утилиты из поставки Kafka создают топики, записывают в них сообщения и читают их. Утилиты лежат в каталоге _bin_ установки, поэтому команды курсов Хекслета имеют вид `bin/kafka-topics.sh --bootstrap-server localhost:9092` и выполняются из этого каталога.

Перед тем как начать, убедитесь, что вы умеете запускать терминал и выполнять в нём команды.

Установить Kafka можно двумя способами. С Docker кластер поднимается готовым стендом и не меняет систему. Без Docker брокер запускается из скачанного архива и требует Java.

В Windows Kafka без Docker запускать неудобно. Для варианта без Docker установите [Windows Subsystem for Linux](https://learn.microsoft.com/ru-ru/windows/wsl/install) (WSL), о настройке мы написали [гайд](https://ru.hexlet.io/blog/posts/ubuntu-linux-in-windows), и выполняйте команды в терминале Ubuntu.

## С Docker

Этот вариант одинаково работает в Linux, macOS и Windows, если установлен [Docker](/docker.md). Для курса Kafka на Хекслете подготовлен [стенд](https://github.com/hexlet-components/kafka-cli-stand). Он поднимает отдельный контроллер и три брокера с номерами `1`, `2` и `3` по адресам `localhost:9092`, `localhost:9093` и `localhost:9094`. На этом стенде выполняются все команды курса, включая опыты с отказом брокера.

```bash
git clone https://github.com/hexlet-components/kafka-cli-stand.git
cd kafka-cli-stand
docker compose up --detach
```

Первый запуск загружает образ и может занять несколько минут. Консольные утилиты лежат в контейнере `cli`, и его рабочий каталог совпадает с каталогом установки из уроков. Каждый новый терминал открывается так.

```bash
docker compose exec cli bash
```

Проверьте, что брокер отвечает.

```bash
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

На свежем стенде команда ничего не выводит и завершается без ошибки. Если клиент печатает предупреждения о подключении, брокеры ещё запускаются, и через несколько секунд команду стоит повторить.

Брокер останавливается и возвращается командами ниже. Они нужны в уроках про репликацию.

```bash
docker compose stop broker-3
docker compose start broker-3
```

Весь стенд останавливается командой `docker compose down`, и данные топиков при этом пропадают. Если утилиты Kafka уже установлены на компьютере, они подключаются к стенду по тем же адресам напрямую, без контейнера `cli`.

## Без Docker

Брокеру нужна Java версии 17 или новее, установить её поможет [инструкция по Java](/java.md). Проверьте версию.

```bash
java -version
```

Скачайте архив последней версии со [страницы загрузок Kafka](https://kafka.apache.org/downloads), раздел Binary downloads. Распакуйте его и перейдите в созданный каталог. Имя каталога совпадает с именем архива, например _kafka_2.13-4.4.0_.

```bash
tar -xzf kafka_2.13-*.tgz
cd kafka_2.13-*/
```

Перед первым запуском хранилище брокера размечается под новый кластер. Команда выполняется один раз.

```bash
KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
bin/kafka-storage.sh format --standalone -t "$KAFKA_CLUSTER_ID" -c config/server.properties
```

Брокер запускается так.

```bash
bin/kafka-server-start.sh config/server.properties
```

Брокер занимает терминал, пока работает, и принимает подключения по адресу `localhost:9092`. Команды курса выполняются во втором терминале из того же каталога. Проверьте, что брокер отвечает.

```bash
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

Брокер останавливается сочетанием Ctrl+C в его терминале. При следующем запуске разметка не нужна, хватает команды `bin/kafka-server-start.sh`.

Данные по умолчанию хранятся в каталоге _/tmp/kraft-combined-logs_, и система может очистить его при перезагрузке. Чтобы топики сохранялись, поменяйте `log.dirs` в _config/server.properties_ на каталог в домашней директории и повторите разметку.

### Настройки для уроков про очистку истории

Брокер проверяет срок хранения раз в пять минут, поэтому в опытах с удалением и уплотнением результат приходится ждать. Добавьте в конец _config/server.properties_ две строки и перезапустите брокер.

```text
log.retention.check.interval.ms=1000
log.cleaner.backoff.ms=1000
```

### Кластер из нескольких брокеров

Уроки про репликацию требуют три брокера. Каждому нужен свой файл настроек с отдельным номером, портом и каталогом данных, и собирать такой кластер вручную долго. Для этих уроков удобнее взять [стенд из раздела про Docker](#с-docker).
