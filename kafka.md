# Установка Apache Kafka

Kafka работает как сервер, который называют брокером. Брокер хранит топики, а консольные утилиты из поставки Kafka создают топики, записывают в них сообщения и читают их. Утилиты лежат в каталоге _bin_ установки и называются `kafka-topics.sh`, `kafka-console-producer.sh`, `kafka-console-consumer.sh` и так далее.

Перед тем как начать, убедитесь, что вы умеете запускать терминал и выполнять в нём команды.

Установить Kafka можно двумя способами. С Docker брокер работает в отдельном контейнере и не меняет систему. Без Docker брокер запускается из скачанного архива и требует Java.

В Windows Kafka без Docker запускать неудобно. Для варианта без Docker установите [Windows Subsystem for Linux](https://learn.microsoft.com/ru-ru/windows/wsl/install) (WSL), о настройке мы написали [гайд](https://ru.hexlet.io/blog/posts/ubuntu-linux-in-windows), и выполняйте команды в терминале Ubuntu.

## С Docker

Этот вариант одинаково работает в Linux, macOS и Windows, если установлен [Docker](/docker.md). Брокер запускается в контейнере `kafka` из официального образа и принимает подключения на порту `9092`.

```bash
docker run -d --name kafka -p 9092:9092 apache/kafka:latest
```

Первый запуск загружает образ и может занять несколько минут. Консольные утилиты входят в тот же образ и лежат в каталоге _/opt/kafka/bin_ контейнера. Проверьте, что брокер отвечает.

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

На свежем брокере команда ничего не выводит и завершается без ошибки. Если клиент печатает предупреждения о подключении, брокер ещё запускается, и через несколько секунд команду стоит повторить.

Оболочка внутри контейнера открывается так. Из каталога _/opt/kafka_ утилиты запускаются коротким путём `bin/kafka-topics.sh`.

```bash
docker exec -it --workdir /opt/kafka kafka bash
```

Порт `9092` проброшен на компьютер, поэтому приложения и утилиты, установленные на компьютере, подключаются к брокеру по адресу `localhost:9092`. Контейнер сохраняет данные между остановками. Остановить его можно командой `docker stop kafka`, снова запустить командой `docker start kafka`.

## Без Docker

Брокеру нужна Java версии 17 или новее, установить её поможет [инструкция по Java](/java.md). Проверьте версию.

```bash
java -version
```

Скачайте архив последней версии со [страницы загрузок Kafka](https://kafka.apache.org/downloads), раздел Binary downloads. Распакуйте его и перейдите в созданный каталог. Имя каталога совпадает с именем архива, например _kafka_2.13-4.4.0_.

```bash
tar -xzf kafka_2.13-*.tgz
cd kafka_2.13-*/
```

Перед первым запуском хранилище брокера размечается под новый кластер. Команда выполняется один раз.

```bash
KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
bin/kafka-storage.sh format --standalone -t "$KAFKA_CLUSTER_ID" -c config/server.properties
```

Брокер запускается так.

```bash
bin/kafka-server-start.sh config/server.properties
```

Брокер занимает терминал, пока работает, и принимает подключения по адресу `localhost:9092`. Утилиты запускаются во втором терминале из того же каталога. Проверьте, что брокер отвечает.

```bash
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

Брокер останавливается сочетанием Ctrl+C в его терминале. При следующем запуске разметка не нужна, хватает команды `bin/kafka-server-start.sh`.

Данные по умолчанию хранятся в каталоге _/tmp/kraft-combined-logs_, и система может очистить его при перезагрузке. Чтобы топики сохранялись, поменяйте `log.dirs` в _config/server.properties_ на каталог в домашней директории и повторите разметку.
